# Discord Rules

These rules are intended to keep the Lumina Discord healthy, welcoming, and useful for builders.

## Core Rules

1. Be respectful.
- No harassment, hate speech, intimidation, or personal attacks.

2. Keep discussion constructive.
- Critique ideas, code, and designs without attacking people.

3. Stay on topic in technical channels.
- Use the right channel for support, language design, ecosystem, showcase, and off-topic chat.

4. No spam or disruptive self-promotion.
- Occasional relevant project sharing is fine; repeated promotion, mass mentions, or low-value links are not.

5. Use readable support requests.
- Include code, errors, versions, target profile, and what you already tried.

6. No unsafe or malicious content.
- Do not share malware, token leaks, credential dumps, phishing links, or intentionally harmful code.

7. Respect privacy.
- Do not publish private conversations, personal information, or sensitive project details without consent.

8. Keep AI/tooling use transparent when relevant.
- If you are sharing generated code, summaries, or benchmarks, say so when it matters for review quality.

9. Use moderator guidance.
- If a moderator asks for a pause, channel move, or behavior change, comply without escalating publicly.

10. Help keep the community useful.
- Prefer reproducible reports, clear titles, and follow-up once your issue is resolved.

11. No politics, religion, gender-war, or other divisive culture-war debates.
- This server is for Lumina, software, learning, collaboration, and community support.
- If a topic is likely to derail the space into ideological conflict, moderators may stop or remove it.

## Support Posting Format

When asking for help, try to include:

- Lumina version
- target (`js`, `wasm-web`, `wasm-standalone`)
- platform/browser/runtime
- minimal code snippet
- error output
- expected vs actual behavior

## Recommended Channel Policy

- `#announcements`: maintainers only
- `#start-here`: onboarding, docs, install links
- `#help`: user support and debugging
- `#language-design`: syntax, semantics, and roadmap discussion
- `#runtime-ui`: rendering, SSR, hydration, routing, UI primitives
- `#showcase`: demos, screenshots, benchmarks, releases
- `#contributors`: implementation and contributor coordination
- `#off-topic`: casual chat that does not belong elsewhere

## Enforcement

Moderation actions may include:

- reminder
- content removal
- warning
- temporary mute
- temporary ban
- permanent ban

Severity depends on impact, repetition, and intent.

## Moderator Principles

- explain actions clearly when practical
- protect users from harassment and abuse
- prefer de-escalation first
- act faster on safety, privacy, spam, and malicious behavior
